# Plan 004 — Phone form mode for the card editor

Written against: commit `094c437` (+ architecture map from explore pass, citations below) · Covers: MOBILE-AUDIT.md Limitation 1 (user-approved direction 2026-10-03) · Status: **PROPOSED — awaiting prototype approval**
Visual reference: `design-plans/prototype-editor-form.html` (phone form UX; renders real listing data read-only for review).

## Evidence chain

- Surface: `index.html` editor at ≤700px. Measured (audit step 07): card canvas at 0.35 floor → 3.5–4.9px effective text, 672px sizer panning in a 390px viewport. Chrome is fixed (94px topbar, ≥40px targets, plan 003) but the editing surface itself is unreadable: a seller cannot proofread what they type.
- Design evidence: MOBILE-AUDIT.md Limitation 1 names form mode as the fix; user approved the direction 2026-10-03. Architecture map (explore, cited inline) proves form mode can bind to the EXISTING state/payload machinery with no data-model change.
- Owner: `js/editor.js` (state :23-33, captureTexts :128-132, hydrate* :74-118, renderFromState :120-126, addSkin :300-306, recountStats :838-853, openPicker :159-193, openVariantModal :364-391, openRankPicker :195-204, asset handlers :904-936, placeThemes :1088-1099), `index.html` (#card fields, #chrome, modals), `css/editor.css`.
- Scope: phone (≤700px) ONLY. Desktop/tablet editor unchanged (D3 carried forward). Export/publish/save/draft/import flows unchanged — they keep reading the hydrated card DOM + state exactly as today.
- Uncertainty: html-to-image capture while the stage is translated off-screen (analysis says card-level capture is ancestor-transform-agnostic; MUST be proven in QA with a real export click from form mode).

## Design decision

At ≤700px the editor defaults to a **native single-column form** (`#formMode`) that edits the same `state` object and keeps the real `#card` DOM hydrated underneath; the card itself stays **laid out but translated off-screen** (`transform:translateX(-200vw)` — never `display:none`/`visibility:hidden`, which would break html-to-image capture and `slots.clientWidth` layout math, explore §8.3). A topbar **PREVIEW ⇄ FORM** toggle swaps between form and the existing scaled-canvas stage (pan/zoom as today) so the seller can always see the real artifact. All pickers/modals (skins, ranks, variants, buddies, cards, import) are the EXISTING ones — the form only provides phone-legible entry points.

**Binding rule (non-negotiable, explore §8.1):** the card DOM is the source of truth at capture time (`captureTexts()` runs inside every `buildPayload()` — save :990, publish :1036/:1150, refreshLayout :1052, post-text :958). Therefore every form write does BOTH: `state.texts[k] = v` AND `card.querySelector('[data-key=k]').textContent = v` (the `applyRank` pattern, :309-311). Every external state mutation (import :820, draft load :1016, edit-mode :1307, boot-restore :1337 — all call `renderFromState()`) re-syncs the form through ONE new hook inside `renderFromState()`.

## Reuse

- State + repaint contract: `renderFromState()` (editor.js:120-126) = applyTheme + hydrateTexts + hydrateRanks + renderAll + hydrateAssets; plus `recountStats()` (:838) on picks changes. Form mode calls ONLY these.
- Pickers/modals unchanged: `openPicker(cat)` (:159), `openVariantModal(cat, idx)` (:364), rank picker (:195-204 → small refactor below), `openBuddyPicker()` (:393), `openCardPicker()` (:436), import modal (:606), shared `#fileInput` + `pendingUpload` flow (:904-936), `CF.resizeToDataUrl` (shared.js:375).
- Element relocation precedent: `placeThemes()` (editor.js:1088-1099) already moves live DOM nodes between topbar and More menu by matchMedia — generalize to `placeRelocatables()` (themes, #layoutSel, #layoutBadge, .pubswitch) with a third target (form LOOK/ART sections at ≤700px). Nodes are moved, never cloned → listeners/ids survive; `refreshLayout()` (:1057-1064) and `buildPayload()` (:1041) keep finding them by id.
- Visual language: form tiles = viewer `.mtile` values (art 64px, tier border, LV badge, one-line name); inputs = notched 44px Chakra Petch fields on `--panel`/`--box` tokens; section cards = `.mbox`-style notch-lg panels. All tokens exist (shared.css:4-31).
- Publish gate (:1116-1147) and recovery-key flow (:1236-1248): untouched — they read state/DOM which the form keeps hydrated.

## Edge cases (MUST handle)
- Text input while card DOM also editable (peek mode): both directions end in DOM+state; form re-syncs on every `renderFromState` and on peek→form toggle (call `syncFormFromState()` when leaving peek) — last-write-wins, same as today's contenteditable model.
- Import flow on phone (modal → applyImport → renderFromState): form fully repopulates via the single hook.
- 0 skins: Skins section shows per-cat ADD rows only; publish gate still blocks (unchanged :1116-1147) with its existing toast.
- 75+ skins: thumb grids scroll within page flow (form page scroll is EXPECTED here — it is an editor, not the buyer surface); per-cat counts in headers.
- Duplicate same-id picks: thumbs are per-array-entry (index-precise) → variant modal Remove splices the tapped instance (precise, unlike card `.rm`).
- Assets as data URLs (quota): unchanged risk profile (save handler already catches :996-998).
- Rotation/boundary crossing 390↔1024: CSS-media default handles form/stage; `placeRelocatables` mq listener restores desktop positions; `stage-peek` cleared above 700px; no stuck off-screen stage (QA gate).
- Export from form mode (no peek): `body.exporting` (+`exporting-full`) capture must produce the identical PNG as peek-mode export — card-node capture is ancestor-transform-agnostic (html-to-image serializes #card itself, shared.js:419-423); QA MUST click real Export in form mode and confirm success toast + non-zero blob (orchestrator verifies download/toast).
- og:image publish path (:1213-1229) re-renders capped layout on the live card — off-screen stage keeps `slots.clientWidth` measurements real (translate preserves layout); QA publishes from form mode in browser-mode (no Supabase write needed if config absent — config IS present, so QA uses a throwaway slug and archives/deletes via the new owner controls, or verifies via console that capture blob > 0 before upload).

## Do NOT
- No changes to `js/shared.js`, `js/layouts.js`, `view.html`, browse files, or any desktop (>700px) styling/behavior.
- No new payload keys, no draft-schema change, no Supabase change, no picker-modal internals change (entry points only).
- Do not `display:none` or `visibility:hidden` the stage/card in form mode (breaks export + layout math).
- Do not clone relocated nodes (ids/listeners must survive); do not bind form inputs inside `#card` (delegation misfire, explore §8.6).
- Do not "fix" the recountStats vs applyImport limited-count drift (ultra vs ultra+exclusive, explore §8.8) — preserve current semantics; note it in Concerns only.

- System: one binding rule everywhere (state+DOM dual write); one sync hook (`renderFromState`); zero duplicated picker logic; `#layoutSel/#layoutBadge/#exportBtn/#showAllCards` always in DOM (refreshLayout/buildPayload dependents, explore §8.4).
- Repository: `npm run lint` → 0 errors 0 warnings; desktop 1920×1080 editor screenshot diff vs pre-change → identical (topbar order logo→themes→layoutSel→badge, 52px); `node --check js/editor.js` clean.

## Stop conditions
- Stop if a real Export-PNG click from form mode produces a blank/failed capture (off-screen assumption wrong) → fallback: auto-enter peek during export (`body.exporting` also removes the translate via an editor.css rule `body.form-exporting #stage{transform:none}` added by the export click handler) and re-verify; if still broken, BLOCK and report.
- Stop if `refreshLayout()`'s chrome writes (:1057-1064) throw when nodes are relocated (they shouldn't — ids persist) → BLOCK with the exact error.
- Stop if publish's og:image re-render measures zero-width slots off-screen → apply the same peek-during-capture fallback.
