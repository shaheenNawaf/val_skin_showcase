Data already in the response, never rendered

Returned by browse_listings_v2

  • • currency — normalised, then discarded. Every price renders a hardcoded $.
  • • negotiable — normalised, then never shown. “Offers only” filters on price === null instead.
  • • code — searchable, but painted only in the quick-view bar.
  • • stats.vp / rp / kc — normalised, never rendered.
  • • status — sold and pending listings are indistinguishable from live ones.

Proposed: where each one appears

  • • currency → real symbol before the amount, from the column.
  • • negotiable → an “open to offers” line under the price, so a buyer knows the price is not fixed before they contact anyone.
  • • code → under the title, and in the search placeholder.
  • • status → corner badge; sold is struck through and unclickable for buying.
  • • WTR / receipts → chips on the card itself, not only in list mode.

The 60-row ceiling

The RPC defaults to p_limit 60 and browse.js passes no arguments, so listings past 60 are not merely hidden behind a control — they are never fetched. “Load more” only helps once the caller passes an offset. This prototype shows the honest state: a visible total, a “showing 60 of N” line, and a disabled button with the reason, so the limit is a known limitation rather than a silent one.
