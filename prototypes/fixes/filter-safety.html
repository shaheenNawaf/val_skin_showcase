A filter that tells you
what it is about to do.

The tier filter shipped with two destructive behaviours the interface hides: Reset rebuilds the card from state.owned, so with no import it empties the card and still reports ✓ Tier filter applied; and the internal snapshot it filters against is never invalidated, so skins you add by hand afterwards silently vanish on the next Apply — again with a green tick. This is a two-step, preview-first, undoable version. Pick a scenario.

Today

One click applies immediately and destructively. The only feedback is a toast that fades in 5 s and always says success.

What will change

One vocabulary, not two

Today the toolbar calls them Select · Semi-prem · Premium · Limited · Melee and the picker ladder in the same window calls them Select · Deluxe · Premium · Ultra · Exclusive. Same five tiers, no cross-reference — and Melee is a weapon class, not a rarity. The proposal drops the toolbar's vocabulary entirely and reuses the picker's.

Implementation notes

What has to change in the code

  • • Delete the module-level allPicks snapshot and its three call sites. Filter state.picks directly.
  • • Split applyTierFilter() into computeFilter() (pure, returns the diff) and commitFilter() (writes).
  • • Keep an undoStack of the pre-filter state.picks.
  • • Gate #tierReset on state.owned.length with an explanatory disabled state.
  • • Persist tier state in the draft next to state.layout.

What I did not touch

  • • The cap semantics stay top N per category, best first — I only made it visible and per-category.
  • • Filter keys select/deluxe/premium/ultra/exclusive are unchanged; only the labels move.
  • • Nothing is committed to staging until you say so.
