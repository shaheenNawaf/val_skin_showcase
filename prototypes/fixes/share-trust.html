Prototype 6 of 6 · Outside the pages

The link is the product.
It renders as nothing.

The previous five prototypes fix what happens inside the pages. This one covers what happens around them — and it is where I found everything the first audit missed. A seller finishes their card, publishes, and pastes the link into Discord or Facebook. That embed is the product's entire acquisition channel. Today it is a text-only stub: og:title is hardcoded to "CardForge — Listing", there is no og:image at all, and the browser tab never says whose card it is. The PNG the seller just spent an hour perfecting — the thing the product exists to make — is not attached to its own link.

The tab title, too — document.title is never set per listing, so ten open listings are ten identical tabs.

One honest constraint. Crawlers do not run JavaScript, so og: tags cannot be written client-side from the fetched listing — they have to exist in the served HTML. This needs one small server-side piece. Netlify already runs the deploy, so the natural shape is a ~20-line Edge Function on /l/:slug that reads the listing row, rewrites the meta tags, and redirects everything else. The image side needs a Supabase Storage bucket: the publish flow already renders the PNG — upload it alongside create_listing, store the URL in the row. Interim step if you want it tomorrow: a static brand card as a single og:image plus the per-listing title. That alone beats a bare URL.

2 · You can publish an empty card

I traced buildPayload() → create_listing: there is no validation between them. The SQL validates slug format, token shape and payload size — not whether the card has content. An empty card with the placeholder text CHANGE NAME and PRICE OFFER publishes straight into the public marketplace and becomes the front page.

3 · Lose your browser, lose your listing

Today — silent single point of failure

Edit access is a random token stored only in localStorage under vc-edit-<slug>. Nothing warns the seller, nothing backs it up. Clear the browser, lose the laptop, or switch machines, and the listing can never be edited or marked sold again — only the database can. For a marketplace where “mark as sold” is the core lifecycle, that is a real loss scenario with zero UI acknowledgement.

Proposed — show the key once, at the moment of trust

recovery key  8f3k-xq2v-9m1d-p7tz

Shown once at first publish, with a copy button and one sentence: “Keep this somewhere safe — it is the only way to edit this listing from another browser.” A re-entry field on the editor (?edit=slug + key) restores control. No accounts, no email, no schema change beyond storing the hash that already exists.

4 · View counts count everything, forever

Measured in the schema

create function bump_views(p_slug text)
  update listings set views = views + 1

– no throttle, no dedupe
– granted to anon
– runs on every page load
– the seller's own refreshes count
– a bot can pump any listing

Why it matters

  • • “101 total views” is on the marketplace front page — it is social proof, and it is inflatable by anyone with a refresh key.
  • • Most viewed is a sort option. The ranking is gameable.
  • • The seller inflating their own count with refreshes is the likeliest case, and it needs no malice at all.
  • • Fix is small: skip the bump when vc-edit-<slug> exists (seller's own browser), throttle per session, and count unique presence viewers as the honest “now” number — that channel already exists.

For the record, the good half of this: “N viewing now” is real. It is a Supabase presence channel per slug, not a faked number. The previous audit never said otherwise; I am confirming it so nobody goes hunting for a bug that does not exist.

Two separate changes, both cheap. Editor: buddies and playercards are only needed if the seller opens the buddy picker or ticks show my full player-card collection — they are the 1.28 MB majority of the boot payload, fetched eagerly for every seller including the ones who never touch either feature. Load them on first use. Buyer: view.html ships the full 209 KB Supabase SDK to do three things, one of which needs it. Listing reads are anon-REST — a plain fetch does them in a kilobyte; keep the SDK only for the presence channel, or drop “viewing now” to a lightweight poll. At 4G speeds the buyer's first paint moves by seconds.
