CARDFORGE · MARKETPLACE REDESIGN

Three directions,
one identity.

The live browse page is text-only: no inventory imagery, no search, no filters — and with one listing it reads as abandoned. Every prototype below keeps CardForge's identity (Manrope + Inter, notched panels, #FF4655) and fixes the fundamentals:

  • Visual inventory previews — real skin art, rank badges, theme colors on every card
  • Working search, theme filters and sorting on all views
  • Prices and "make offer" states surfaced (columns already exist in the DB)
  • Trust flags: WTR, receipts, owner history, view counts
  • Sparse-market handling — the page looks intentional with 1 listing or 100
  • Proper empty states with a reset action
  • Loading skeletons instead of blank space
  • Mobile-first responsive layouts + keyboard/a11y basics

Recommendation

Start with B (Gallery). The marketplace's real bottleneck today is not scale — it is desire: one listing, zero imagery, no reason to click. Gallery turns each card into the product it already is, and its featured slot keeps working when the catalog is tiny. Steal two things from the others on the way: C's utility tiles for sparse stretches, and A's list view + facet sidebar once the catalog passes ~30 listings.

What production integration needs

  1. Extend the browse_listings RPC (supabase/migrations) to return price, currency, rank keys, top skin icons, seller name/avatar and flags — all already inside listings.payload.
  2. Pick a direction (or mix) — prototypes are pure static files, nothing in the live app was touched.
  3. Port the chosen layout into browse.html + css/browse.css + js/browse.js, keeping the Supabase fetch and the localStorage-only fallback.
  4. Optional later: generate a real card thumbnail (scaled PNG) at publish time for pixel-perfect previews instead of re-rendered minis.
